# Everyday money tools: approved implementation plan

User approved all six features and delegated placement/design. Keep navy/purple, concise labels, normal touch targets and circle-question help. No instrumentation. Execute inline with one final fresh source review and one CI build after grouped implementation.

1. Cash entry: Activity Add entry sheet, income/expense, account, amount, date and category. Save in canonical transactions; no invented balance and no duplicate withdrawal expense. Owned accounts only; structural categories excluded. Identity token makes repeated submit idempotent.
2. Splits: transaction detail Split payment sheet with editable category/amount rows. Require >=2 positive parts exactly equal to principal. Allocations stored separately; canonical transaction and cash flow unchanged. Budget and report category projections consume allocations, fees stay separate, refunds follow original allocations. Remove split supported. Exclude/reclassify clears obsolete allocations.
3. Flexible budget: monthly/weekly/payday periods, anchor day, carry-unused toggle in existing budget editor. Defaults unchanged for existing budgets; per-period reads, effective limit and alerts agree. Carry begins when opted in, subtract spending, no historical free money before start; calendar boundaries honor timezone and short months.
4. Balance check: Accounts Check balance flow, selected owned account, current recorded figure vs user-entered actual figure and delta. Show recent activity, never create income/expense to hide a difference. Explicit Save observed balance confirms a dated observation; backdates/future dates disallowed initially.
5. Statement import: Activity Import statement flow via Android file picker. Supported CSV only: date, description, amount (signed), optional reference, or debit/credit columns; dates yyyy-MM-dd or dd/MM/yyyy. UTF-8, bounded size/rows, strict validation and no silent dropped invalid rows. Account selected explicitly. Preview/select, flag duplicates against all sources and within file. Imported rows stay in review until categorized; transfer-like entries require review. Atomic save, no automatic balances, no upload.
6. Recurring suggestions: use existing detector, Bills compact expandable suggestion panel; accept creates bill with editable cadence/date and existing reminders, dismiss persists. No automatic charges or fabricated transactions.

New domain policies: exact money/CSV parser, split apportioning/refund, flexible-period and carry calculation. JVM tests first for rounding, overflow, invalid CSV, quoted/newline fields, date/period boundaries and rollover. Repository writes synchronized and transactional. Schema35 adds only budget options and allocations; schema34 encrypted backups normalized by adding empty tables, then full schema validation. New tables included automatically in encrypted backups. Current projections and existing tests retained with optional allocation callback defaults.

Review focus: double counting, source duplicates, user consent/ownership, migration/backup restore, refunds/fees, period and reminder alignment, error/loading/cancellation states, safe imports and simple accessible UI. Preserve unrelated in-flight work. New PR unmerged until user asks.
